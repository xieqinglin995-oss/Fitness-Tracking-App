## Release 模拟器实测

1. 卸载测试用 Debug 包，关闭模拟器 WiFi 与蜂窝数据，安装正式签名 versionCode 1；离线首次启动正常，空状态无演示数据。
2. 通过界面保存 80.25 kg，系统文件选择器导出 JSON，拉取文件核对整数克为 80250，只有一条记录。
3. 从系统选择器导入完整验收文件：3 条体重、2 日计划、2 条实际、1 个模板及斤单位/目标。确认前展示数量和替换范围；先选择并保存原数据安全备份，再恢复。拉取安全备份确认包含原来的 80.25 kg。
4. 安装同签名、更高 versionCode 的 Release 包覆盖，不卸载。结束进程并重开，界面保留单位与体重。
5. 再通过系统选择器导出升级后的完整 JSON，与导入文件逐字段比较：所有对象、ID、目标与实际快照、日期、关联和设置完全一致。
6. 检查今天、计划、趋势页面并保存截图。截图记录是验收输入，仅存在于测试模拟器，不随 APK 初始化。

以上验证使用相同 schema 1；不能替代将来数据库版本迁移或目标手机的真实升级验证。

## 需目标真机验收

- Android 8.0 及用户实际手机系统的安装、键盘、系统返回、字体放大与屏幕适配。
- 飞行模式首次启动及进程结束、重启设备后的持久化。
- 系统文件选择器导出、恢复和取消；空间不足与文件提供方写入失败。
- 设备时区切换、午夜训练归属日期保持不变。
- 实际使用版本到下一版同签名覆盖升级；当前只能验证首版到更高 versionCode 的同 schema 升级，不代表未来数据库迁移已验收。
- 5 年、每天 10 项训练规模的真机性能。尚未测量，不承诺已达到 1 秒 / 2 秒性能目标。

## 数据保护设计

恢复校验在写入之前完成。用户确认后，通过系统保存入口先写完当前数据的安全备份，再调用单个 `withTransaction` 完整替换。数据库约束为日期唯一、实际项目关联唯一及 RESTRICT 外键。存在独立唯一索引的表用明确的插入/更新，其他表差量 Upsert，不使用会删除重插父行的 SQLite REPLACE；没有启用 destructive migration。

训练的名称、类型、目标和实际值分开保存。替换计划保留已有实际记录的项目；实际删除需先确认，不会因删除模板、设休息或复制而静默丢失历史。
