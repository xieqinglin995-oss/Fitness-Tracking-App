# 好好健身 V1.3 实现与验收

日期：2026 年 11 月 12 日  
版本：1.3.0 / versionCode 7  
发布包：`com.xieqinglin.fitness`，最低 Android 8.0。

本版按 [后续优化方案](后续优化方案.md) 落地个人力量＋有氧记录流程。下面分别说明交付能力、已验证范围和仍需目标手机验证的事项。

## 实现范围

| 方案项 | 本版行为 |
| --- | --- |
| F01 输入保护 | 普通实际弹窗补齐未保存提示；数字清空、状态与备注变化也识别为修改 |
| F02 图表和口径 | 横向手势查询、纵向保留页面滚动；跨年显示年份；训练日期与周统计共用确认规则；日期条改为惰性列表 |
| F03 首页 | 已称重后显示紧凑摘要，可展开/收起；训练区显示接着做的动作和已确认组；继续训练定位到下一待确认组 |
| F04 快速填写 | 专注模式逐组使用上次/上一组，次数 ±1，负重步长可选；确认后收键盘并定位下一组 |
| F05 加减组 | 实际组带稳定 ID；复制上一组、空白组、移除未确认组；确认状态随 ID 保留，不随下标错位 |
| F06 有氧 | 正计时、按目标倒计时、暂停/继续、填入用时；分秒输入兼容旧小数分钟；按该项目的实际用时和距离计算配速 |
| F07 收尾 | 完成、跳过、未完成分开总结；可以保留部分并结束，不自动完成剩余组；未核对的计时先返回处理；当次总结可保存 |
| F08 模板 | 选择采用哪些已确认实际，预览原模板与新的结构；明确替换后生效，默认只保留本次，不改历史和其他日期 |
| F09 备注 | 本次动作备注与动作固定提示分开；旧同名记录由用户勾选后归集，不自动把不同器械合并 |
| F10 排期 | 从自己的模板选择星期和起止日期，最多 12 周；具体冲突预览、默认保留已有日期；同批生成幂等；可另行预览更新本批未来未开始日期 |
| F11 回看 | 力量、有氧和日期/备注检索；同动作身份过滤；本周力量/有氧及并集天数；最近两个 7 日窗口均值和样本天数 |
| F12 长历史 | 日期/实际索引、惰性日期条、删除按 900 个 ID 分批；保留统计与历史校验；性能预算仍需参考手机测量 |
| F13 自动备份 | 默认关闭；系统授权目录；变更合并约 3 秒后写完整 JSON，回读校验；只轮换本安装登记的文件，保留最近 8 份；关闭不删文件 |
| F14 桌面组件 | 今日记录、快速称重两种组件；入口进入对应操作；默认仅显示是否称重，具体体重需主动开启 |
| F15 提醒 | 星期选择、今日跳过、稍后 30 分钟；称重/训练分渠道；反馈总权限与渠道状态，尊重旧渠道被关闭的选择 |
| F16 布局 | 专注录入和称重摘要适应窄屏/大字体，计划提供大字日期列表；未将此等同于完整 TalkBack 或所有手机适配验收 |
| F17 日期边界 | 新增和改日期检查与存量结构校验分开；日期回拨不阻挡其他保存；前台/日期广播刷新今天；恢复点使用进程内单调时钟限流 |

休息与有氧计时是独立状态。有氧计时不会自动完成项目；单项和批量完成均核对未填入的计时；训练总历时没有记录时不展示，更不会从训练组或计划目标反推。

## 数据和升级

- Room 从 schema 1 升级为 2，新增独立 metadata 表保存动作定义、总结与排期来源，避免把多年内容挤在单条设置记录中。原表和数据保留，使用显式 `MIGRATION_1_2`。
- 新完整备份为 schemaVersion 4，继续支持 v1/v2/v3。新增内容纳入备份、数量及结构校验。v4 不能直接交给旧版恢复。
- 旧训练组 ID 不在读取时随机生成。进入编辑时按原项目与位置确定兼容标识，后续新组拥有独立 ID；未确认值仍为草稿。
- 日期回拨后的存量记录保留归属日期。外部恢复若含晚于设备今天的日期，预览会特别说明，确认恢复不自动改日。
- 自动目录、提醒、主题、计时及组件隐私属于本机偏好，不随健康记录备份迁移。换机后重新授权目录。

已在正式安装实例上从 1.2 覆盖到 1.3，未卸载。通过系统文件选择器导出升级前 v3 与升级后 v4，对照全部旧字段：30 条体重、3 日计划、3 条实际记录、1 个模板及单位均相同，包括原已确认组。新增元数据在升级时为空。

## 构建与测试

JDK 17、SDK 35、Gradle 8.11.1，使用项目固定依赖，离线构建。

```powershell
.\gradlew.bat assembleDebug assembleDebugAndroidTest assembleRelease testDebugUnitTest lintDebug --offline --console=plain
```

- 74 项 JVM 单元测试通过：原有业务、精度、批量与备份回归；新增分秒输入、独立计时、配速、混合统计、周期幂等、未来批次保护、稳定组身份、v4 及旧格式兼容、恢复点回拨限流。
- 26 项设备测试通过，环境为独立 Android 9 / API 28 模拟器。覆盖 Room 1→2 实际迁移、事务/约束、超过 SQLite 参数上限的删除、日期回拨、普通录入退出保护、删中间组后保留末组确认、力量切到有氧时的页面定位、有氧填入与部分结束、批量完成不覆盖未核对计时，以及组件的实际宿主绑定和隐私切换。
- 组件测试仅在验收模拟器向 `.debug` 宿主临时授予绑定能力，结束后撤销；正式 App 不申请该权限。CI 同样先安装调试包，再设置测试宿主。
- Lint 无错误，18 条警告及 1 条信息；内容为图标配置、RemoteViews 背景推断、KTX 写法及快捷方式统计等建议，未宣称零警告。
- Release 使用原签名，签名指纹与历史版本相同；文件摘要见 [SHA256SUMS.txt](../releases/SHA256SUMS.txt)。

## 使用边界

自动备份在应用进程内合并执行，未完成的变更下次打开时重试；没有承诺应用被结束后仍按某个时刻后台备份。写入文件提供者不等于云端同步已经完成。JSON 未额外加密，选择位置前界面会说明。

提醒使用非精确系统调度；运动/休息计时不承诺进程被系统结束后响铃。设备重启后有氧用时需要核对；运动计时不申请定位、不记录 GPS 路线。

本轮未完成目标真机性能预算、TalkBack 全流程、最低 API 26、Android 13+ 实际通知授权、厂商省电及不同文件提供者的全部验证。没有把此前五年样本的跳帧日志换算成优化后的帧率，也没有宣称达到所有性能目标。

目标体重区间、自动训练处方、设备同步、云账号和多设备冲突处理没有加入本版；当前单值目标仍可使用。
