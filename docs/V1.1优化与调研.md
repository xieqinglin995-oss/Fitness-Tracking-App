# V1.1 使用体验优化与调研

日期：2026 年 11 月 12 日  
目标：解决个人使用反馈中的批量完成缺失、界面层级不清和称重单位入口不明显，并减少重复操作。

## 用户反馈与实现范围

| 反馈或发现 | 本次调整 | 行为边界 |
| --- | --- | --- |
| 每个训练项目必须分别进入表单才能完成 | 今天页、计划页增加批量完成；单项增加快捷完成 | 确认前可多选、全选或取消全选；未来日期不允许完成 |
| 不希望已有实际值被批量操作覆盖 | 未记录项目使用计划值，进行中项目保留实际值 | 已完成及已跳过项目保持原样；整体事务提交 |
| 批量误点 | 操作后提供撤销 | 恢复本次操作前的实际记录；若记录随后被修改，拒绝覆盖后续修改 |
| 称重时找不到斤 | 在录入框直接展示公斤与斤切换 | 自动换算、显示另一单位的对应值；保存后记住体重单位 |
| 体重用斤但器械负重习惯用公斤 | 体重与训练负重分别设置单位 | 升级时保留旧单位偏好，不修改任何底层重量 |
| 首页首屏信息不足 | 删除宣传大标题，压缩卡片，突出体重和训练进度 | 保留具体日期，历史体重不冒充今日体重 |
| 计划页一周需要左右滚动 | 七天平分一行，简化日期状态；低频操作集中到更多菜单 | 大字体和实际手机仍需验证；保留复制、改期及模板能力 |
| 训练记录重复输入 | 项目卡展示同名同类型的上次已完成实际；录入时可主动复用 | 只查当前日期之前的记录，不自动覆盖当前目标或已填写实际 |
| 图表说明占空间，目标线压缩波动 | 最近体重和阶段变化置顶；均值与目标线可切换 | 目标线默认关闭；缺失日仍断线，统计口径不变 |
| 不清楚是否备份过 | 设置显示最近成功导出时间 | 文件关闭写入成功后才更新时间；此时间仅属于本机，不冒充旧备份的导出时间 |

## 批量完成的具体规则

1. 打开时默认选中当天所有未记录或进行中的项目，可取消部分项目。
2. 未记录项目按当前计划目标创建实际记录；必须先确认，不能将未执行的计划自动当作完成。
3. 进行中项目只改变完成状态，保留实际值、名称和目标快照。
4. 已完成和已跳过项目不可被此次批量操作改写。没有可完成项目时禁用入口。
5. 提交时重新读取数据库，确认项目仍属于该日期；所有改动在同一个 Room 事务内保存。
6. 完成后 Snackbar 提供撤销；撤销只影响本次变动，不恢复整个数据库。影响到的记录已被修改或删除时，提示逐项修正。
7. 单项目快捷完成使用相同的确认与保存规则；需要不同实际值时进入填写实际。

## 单位与旧数据兼容

体重和负重继续以整数克保存。录入时切换单位会自动转换显示，保留原始整数克，避免 160.01 斤转换成公斤再切回时丢失精度；用户主动编辑数字后，以新输入为准。

原本的设置字段 `unit` 继续表示体重单位，新增 `loadUnit` 表示训练负重单位。旧数据库设置缺少新字段时，默认继承原来的单位。数据库表结构不变，因此 Room schema 仍为 1，无需破坏性重建。

新备份格式为 schemaVersion 2，包含两个单位。导入继续接受 v1 备份，显式补齐旧设置的负重单位，再执行完整字段与关联校验。v2 备份不可直接交给旧版 App 恢复；覆盖升级使用同一发布签名和更高 versionCode，保留既有数据。

调试包使用独立 applicationId 后缀 `.debug`，测试数据与正式安装实例分开。

## 同类产品调研

本轮为官方公开资料调研，没有把网页描述当作安装实测，也没有将国外产品的磅单位描述为支持斤。

| 产品 | 官方资料中核实的行为 | 本产品采用结论 |
| --- | --- | --- |
| Strong | 逐组勾选完成，另有 Finish 结束训练；允许未完成所有动作就结束 | 区分结束训练与批量标记完成，本产品明确确认哪些项目按什么数值完成 |
| Hevy | 单独展示上次训练值，可以按任意训练或相同模板查看 | 展示历史实际供参考，用户主动复用；首版保守匹配同名同类型项目 |
| StrongLifts | 称重录入中提供单位选择；体重与动作负重可使用不同单位；图表可显示 7 日平均 | 单位切换放到录入当下，体重和负重设置独立；本地化增加斤 |
| FitNotes | 身体指标可配置单位，支持跟踪、历史和图表；设置提供备份恢复 | 保持简单的记录与趋势结构，将备份状态放在设置中 |
| Happy Scale | 原始日常波动之外使用移动平均观察趋势 | 保留原始测量与均值，避免为了曲线连续而填补缺失记录 |
| Google Fit | 体重图支持切换时间范围，并区分测量数据与近期平均趋势 | 数据摘要优先，范围切换明确，不把趋势当成新测量值 |

本轮没有找到足以证明上述产品统一采用本项目批量填值规则的资料；多选确认、保护实际值和局部撤销是结合本次用户反馈作出的设计。

## 后续候选

先使用本轮改动收集实际反馈，再考虑定时提醒、CSV 导出或更细粒度的逐组勾选。自动推荐计划、健康设备接入和多设备同步仍不进入本轮范围。
